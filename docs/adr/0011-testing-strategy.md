# ADR-0011: Testing strategy — pyramid, testcontainers, and ffmpeg confinement

- **Status:** Accepted
- **Date:** 2026-08-25

## Context

The interesting behaviour in this system is not in functions, it is in
interactions: redelivery, rebalance, offset commit ordering, late SSE subscribers,
the packaging join. Pure unit tests cannot reach any of it, and a mocked Kafka
proves only that the mock behaves as imagined.

Two hard environment facts shape this:

1. **`ffmpeg` and `ffprobe` are not installed on the development machine.** They
   exist only in the worker image.
2. Real video files are large and slow, and the pipeline's correctness has almost
   nothing to do with video content.

## Decision

**A three-layer pyramid, with real infrastructure at the integration layer.**

**Unit (`tests/unit/`, no I/O, milliseconds).** Envelope round-trip and
unknown-field tolerance; rendition-ladder selection from *synthetic* ffprobe JSON
(no binary needed); retry/backoff arithmetic; failure classification; object-key
builders; the packaging completeness predicate. Target: the decision logic of
every stage is unit-testable because it is pure — a design constraint, not just a
test goal.

**Integration (`tests/integration/`, testcontainers, seconds).** Real Kafka in
**KRaft mode**, real Postgres, real MinIO, spun up per session. Mandatory cases:

- redelivery of the same message produces exactly one object and one row (ADR-0005);
- a handler that outlives `max.poll.interval.ms` does **not** get evicted and does
  **not** cause reprocessing (ADR-0004) — the single most valuable test here;
- terminal failure lands in the DLQ with reason headers; transient failure walks
  the retry tiers;
- projector replay is idempotent (ADR-0007);
- SSE: late subscriber gets snapshot + subsequent deltas; two API instances with
  unique groups both receive an event; `Last-Event-ID` replays without duplicates
  (ADR-0008);
- concurrent rendition finishers elect exactly one packager (ADR-0013).

**E2E (`tests/e2e/`, full compose + Playwright, a minute).** Upload the fixture
through the real browser flow, assert every rendition object exists, every tile
turns ready **without a reload**, `master.m3u8` is valid, and the failure path
shows a reason in the UI.

**ffmpeg confinement.** Tests that shell out to ffmpeg are marked
`@pytest.mark.ffmpeg` and run inside the worker image (`make integration` runs
the suite in Docker); locally they skip with a clear message. Anything else must
work on a bare machine.

**Fixture:** a 2-second, 640×360 clip generated by
`ffmpeg -f lavfi -i testsrc=size=640x360:rate=15 -t 2` plus a `sine` audio track,
built once into the test image. Also a deliberately corrupt file (truncated
header) for the DLQ path. **No large media in git.**

Supporting choices: `pytest` + `pytest-asyncio`; `testcontainers[kafka,postgres]`;
`httpx` ASGI transport for API tests; `hypothesis` for the ladder-selection
property ("never upscale"); `freezegun` for retry timing; coverage gate on
`libs/pipeline` (the shared blast radius) rather than a repo-wide percentage.

## Alternatives considered

- **Mock the Kafka client in "integration" tests.** Rejected: every bug this
  system will actually have — rebalance, commit ordering, partition assignment —
  is invisible to a mock.
- **A single shared long-lived docker-compose for tests.** Rejected: leaks state
  between runs and makes CI flaky; testcontainers gives per-session isolation.
- **Embedded/in-memory Kafka (e.g. a Python fake).** Rejected: not a broker, so
  it cannot reproduce the behaviours we care about.
- **Real sample videos as fixtures.** Rejected: slow, large in git, and they test
  ffmpeg rather than our pipeline. One realistic file stays available as an
  opt-in manual soak test.
- **Chasing 100% coverage.** Rejected as a goal; the mandatory-case list above is
  the actual bar.

## Consequences

- CI needs a Docker-capable runner and is slower than a pure-unit suite; the
  three layers run as separate CI jobs so unit failures report in seconds.
- Local development can run unit tests instantly but must use Docker for anything
  touching ffmpeg — written into AGENTS.md so it is not rediscovered painfully.
- The long-transcode rebalance test is inherently slow (minutes). It runs on a
  reduced `max.poll.interval.ms` to stay fast while testing the same code path.
